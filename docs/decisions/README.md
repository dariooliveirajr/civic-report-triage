# Architecture Decision Records

An ADR records one decision: the situation, the options, what was chosen and why, what it costs, and when to look at it again. ADRs are not rewritten when a decision changes; a new ADR replaces the old one and the old one is marked "Superseded".

| ADR | Decision | Status | Date |
| --- | --- | --- | --- |
| [0001](0001-backend-boundary.md) | One backend codebase with three entry points | Accepted | 2026-11-26 |
| [0002](0002-koeln-only-data-model.md) | Köln only: no `city` column in the data model | Accepted | 2026-11-26 |
| [0003](0003-code-structure.md) | Strategic DDD with domain folders, interfaces only at external boundaries | Accepted | 2026-11-27 |

Each ADR uses the same sections: Context, Options, Decision, Consequences, Revisit when.
